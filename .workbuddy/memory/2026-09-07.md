## 阻断级 bug：mktcap 恒 NaN → 回测结果为空

提前用 194 只跑单时点 `screen` 暴露出来的，否则等全量抓完才发现要重来。

- **现象**：`screen` 输出"无候选"；逐层定位发现 L1 build_universe 正常(193只)，但 **L2 compute_metrics 返回 0**
- **根因**：`WeStockFetcher.prices()` 里 `total_share`/`mktcap` 是**刻意留空**的(westock.py:344-345)，市值必须调 `attach_shares()` 用财报 `total_share` 按**公告日** point-in-time 回填后再算 `close_raw × total_share`(westock.py:369-375)。`fetch_real.py` 只调了 `prices()` 从未调 `attach_shares()` → mktcap 全 NaN → `compute_metrics` 的 `if not np.isfinite(mc) or mc <= 0: continue` 把**所有**股票跳过 → 回测为空
- **这个设计本身是对的**：用最新股本算历史市值会抹平增发稀释，属前视偏差。错的只是漏调。
- **修复**：
  1. 写 `tests/attach_shares.py` 一次性补算（`save_prices` 按 `(code,date)` 去重保留最新，可直接覆写覆盖 NaN 行）
  2. `fetch_real.py` 行情抓完后补上 `attach_shares` 调用，防止以后重跑再漏
  3. `tests/wait_and_backtest.sh` 流程改为：等抓取结束 → 补算市值 → 校验(coverage≥280 且 mktcap 有效率≥0.9) → 才跑回测
- **已验证**：`attach_shares` 逻辑正确（`merge_asof(direction="backward")` 按公告日回填），小样本验证通过：2019-06-01 用 5 亿股→5.0e9，2020-06-01 用 6.27 亿股→6.27e9

### 另一个坑：读 prices.parquet 会与抓取进程并发写冲突
抓取进程每抓完一只就 read+concat+write 整个 parquet，此时读取可能读到"4 bytes"损坏文件（ArrowInvalid）。
→ 抓取进行中不要读 prices.parquet，等结束后再操作。

## 真实数据才暴露的 4 个 bug（合成数据从未触发）

1. **市值恒 NaN（阻断级）**：抓取流程漏调 `attach_shares()` → 回测为空（详见上节）
2. **`profit_growth_5y` 变复数**：`(gpa_now/gpa_old) ** 0.2`，当 gpa_old 为负（亏损企业）
   时比值为负，负数开 0.2 次幂在 Python 返回 **complex**，整列变 complex128，
   `groupby.rank` 直接抛 `TypeError: No matching signature found`。

4. **`backtest_report` 不认 full 模式**：只遍历 `("in_sample","out_of_sample")`，
